# OrderGuard: аналитический проект по T-Invest API

Учебный проект системного аналитика: проектирование сервиса **OrderGuard**, который гарантирует, что команда на выставление заявки не превратится в дубль, не теряет события исполнения при обрыве стрима и вовремя сообщает пользователю о значимом.

> Проект независимый, не связан с Т-Банком и не является инвестиционной рекомендацией. Заглушка на Go не торгует и не ходит к реальному брокеру. Факты о внешнем API помечены статусами ✅ (подтверждено документацией) и ⚠️ (проверить), см. [docs/00-context.md](docs/00-context.md#6-источники-и-статус-проверки-фактов).

## Главные идеи

1. **Идемпотентность.** Один ключ даёт одну заявку. Повтор после таймаута безопасен только с тем же ключом.
2. **Честный статус.** Состояние `UNCONFIRMED` («итог уточняется») вместо ложной ошибки.
3. **Стрим быстрый, сверка надёжная.** События применяются сразу, а истину устанавливает сверка после переподключения и по расписанию.
4. **Исполнение сильнее отмены.**
5. **Токен не лежит в базе и не попадает в журналы.**

## Запуск заглушки

```bash
cd stub
go test -race ./...
go run ./cmd/orderguard   # слушает :8080, поддельный брокер
```

Пример:

```bash
curl -i -X POST localhost:8080/v1/orders \
  -H 'Idempotency-Key: 6f1c2a52-6f6b-4d57-9a7e-0b1f5d1c2e11' \
  -H 'Content-Type: application/json' \
  -d '{"instrumentId":"BBG004730N88","direction":"BUY","orderType":"LIMIT","quantityLots":"10","price":"250.50"}'
```

Повторите ту же команду: вернётся `200` и та же заявка, а не вторая.

## Как проверить документацию

- Диаграммы в формате Mermaid отображаются на GitHub; отрисованные картинки лежат в `docs/img/`.
- Контракт проверяется любым валидатором OpenAPI 3.0.
- Матрица трассируемости показывает, какие требования покрыты сценарием, контрактом и тестом.
