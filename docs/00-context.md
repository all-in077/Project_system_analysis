# 00. Контекст, цели и границы

## 1. Зачем этот документ

Учебный аналитический проект: проектирование сервиса **OrderGuard** поверх публичного [T-Invest API](https://developer.tbank.ru/invest/). Это не реализация торговой системы и не инвестиционная рекомендация. Цель проекта — показать, как нечёткая потребность превращается в проверяемую спецификацию: требования, сценарии, состояния, контракты, ошибки, риски.

Проект независимый, не связан с Т-Банком и не использует его внутренних данных. Все факты о внешнем API взяты из публичной документации и помечены статусом (см. раздел 6).

## 2. Проблема

Инвестор или небольшая команда выставляет заявки на биржу через API. Типичные боли:

1. **Дубли заявок.** Запрос ушёл, ответ не пришёл (таймаут). Повторить опасно: можно выставить вторую заявку и купить вдвое больше.
2. **Неизвестный итог.** После таймаута неясно, выставлена заявка или нет.
3. **Пропущенные события.** Стрим обрывается, и исполнение заявки остаётся незамеченным.
4. **Шум.** Частичные исполнения дают десятки одинаковых уведомлений.
5. **Лимиты и ограничения.** Заявка выше порога требует подтверждения по СМС и «зависает» в автоматическом потоке.

## 3. Цель продукта

OrderGuard принимает от пользователя команды на выставление и отмену заявок, гарантирует, что одна команда не превратится в две заявки, постоянно сверяет своё состояние с брокером и вовремя сообщает пользователю о значимых событиях.

**Измеримые цели (стартовые, требуют согласования):**

| Цель | Метрика | Значение |
|---|---|---|
| Нет дублей | Доля команд, породивших более одной заявки | 0 |
| Быстрая новость об исполнении | Время от события у брокера до уведомления, p95 | ≤ 5 с |
| Честность статуса | Доля заявок в состоянии «неизвестно» дольше 60 с | ≤ 0,1 % |
| Устойчивость | Потеряно событий исполнения после обрыва стрима | 0 (восстанавливается сверкой) |

## 4. Границы

**В границах:**
- выставление, отмена, замена лимитных и рыночных заявок (через собственный API);
- отслеживание статусов, сверка с брокером;
- уведомления об исполнении, отклонении, отмене, деградации данных;
- работа в песочнице и в боевом режиме (переключатель окружения);
- безопасное хранение токена доступа.

**За границами (осознанно):**
- торговые стратегии и рекомендации «что купить»;
- стоп-заявки и опционы (в первой версии);
- пополнение и вывод средств, налоги;
- мобильное приложение (описан только backend и контракт).

## 5. Стейкхолдеры и роли

| Роль | Интерес |
|---|---|
| Инвестор (пользователь) | Не получить дубль, не пропустить исполнение |
| Владелец продукта | Доверие пользователей, понятная стоимость поддержки |
| Разработка | Однозначные контракты и состояния |
| Служба поддержки | Понятные статусы и журнал, чтобы ответить «что с моей заявкой» |
| Служба безопасности | Токен не утекает, действия пользователя журналируются |
| Брокер (внешняя система) | Нагрузка в пределах лимитов |

## 6. Источники и статус проверки фактов

Метки в документах: **✅** — подтверждено публичной документацией на дату работы; **⚠️** — предположение или то, что нужно проверить по актуальной документации и контракту перед реализацией.

| Факт | Статус |
|---|---|
| Методы заявок: `postOrder`, `getOrders`, `getOrderState`, `cancelOrder`, `replaceOrder`; поток сделок `TradesStream` | ✅ |
| Входной `order_id` в `postOrder` — ключ идемпотентности; в ответе `order_id` — биржевой идентификатор заявки; в ответах других методов ключ называется `order_request_id` | ✅ |
| Уникальность ключа идемпотентности отслеживается за последний месяц | ✅ |
| Повторный `postOrder` с тем же ключом не создаёт вторую заявку; возвращается ошибка с кодом 30057 | ✅ (точная семантика ошибки — ⚠️, см. OQ-1) |
| `getOrders` возвращает только активные заявки; исполненные пропадают | ✅ |
| `getOrderState` содержит массив `stages`, глубокой истории нет, по заявкам старше суток данных может не быть | ✅ |
| `replaceOrder` — отмена и выставление новой заявки; ошибка 30059 при невозможности отмены | ✅ |
| Заявки дороже 30 млн рублей нельзя выставить через API без подтверждения по СМС | ✅ |
| Отрицательная цена допустима только для фьючерсов | ✅ |
| Сервер стрима периодически шлёт ping-пакеты | ✅ |
| Для опционов доступны только лимитные заявки | ✅ |
| Адреса песочницы (gRPC `sandbox-invest-public-api.tbank.ru:443`, REST-вариант) | ✅ (по константам открытого Go-клиента) |
| Перечень статусов исполнения заявки (`NEW`, `PARTIALLYFILL`, `FILL`, `CANCELLED`, `REJECTED`) | ⚠️ имена из контракта по памяти, сверить |
| Конкретные значения лимитов запросов по методам и стримам | ⚠️ взять из страницы «Лимиты» |
| Воспроизводит ли стрим пропущенные события после переподключения | ⚠️ не подтверждено, проектируем так, будто нет (OQ-2) |
| Виды токенов (только чтение, полный доступ, по счёту) | ⚠️ проверить |

Источники: страница [«Описание — инструменты T-Invest API»](https://developer.tbank.ru/invest/services/orders/head-orders), [Go-клиент в pkg.go.dev](https://pkg.go.dev/github.com/acidsailor/tinvest@v0.6.0). Часть страниц документации (FAQ по заявкам, стрим заявок, лимиты) закрыта для автоматического чтения, поэтому прочитайте их вручную и обновите метки ⚠️.

## 7. Глоссарий

| Термин | Значение |
|---|---|
| Заявка (ордер) | Поручение на покупку или продажу инструмента |
| Идемпотентность | Повтор одной и той же команды не меняет результат сверх первого выполнения |
| Ключ идемпотентности | Уникальный идентификатор команды (UUID), который клиент выбирает сам |
| Сверка (reconcile) | Сравнение собственного состояния заявок с состоянием у брокера и устранение расхождений |
| Стрим | Постоянное соединение, по которому брокер присылает события |
| Песочница | Тестовая среда брокера без реальных денег |
| Частичное исполнение | Заявка исполнена не на полный объём |
| Неподтверждённое состояние | Итог отправки заявки неизвестен (таймаут, обрыв) |
