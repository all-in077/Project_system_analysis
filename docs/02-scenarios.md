# 02. Сценарии

Каждый сценарий связан с историями из [01-user-stories.md](01-user-stories.md). Диаграммы последовательностей: [04-integration.md](04-integration.md).

## S-1. Основной: выставить заявку (ORD-1, ORD-2, NTF-1)

| Шаг | Действие |
|---|---|
| 1 | Пользователь отправляет `POST /v1/orders` с `Idempotency-Key` |
| 2 | Сервис проверяет формат, права токена, ограничения (ORD-6, ORD-7) |
| 3 | Сервис сохраняет заявку в статусе `CREATED` вместе с ключом, затем переводит в `SENDING` |
| 4 | Сервис вызывает `postOrder` у брокера, передавая ключ как `order_id` |
| 5 | Брокер подтверждает, сервис сохраняет биржевой идентификатор, статус `NEW` |
| 6 | События стрима приводят к `PARTIALLY_FILLED` и `FILLED` |
| 7 | Пользователь получает уведомление об исполнении |

**Постусловие:** по одному ключу существует ровно одна заявка.

## S-2. Альтернативные потоки

| ID | Условие | Результат |
|---|---|---|
| S-2.1 | Повтор запроса с тем же ключом и теми же параметрами | Возвращается существующая заявка, `200 OK` |
| S-2.2 | Тот же ключ, другие параметры | `409 IDEMPOTENCY_KEY_REUSED` |
| S-2.3 | Заявка исполняется частями | Накопление, одно агрегированное уведомление (NTF-2) |
| S-2.4 | Пользователь меняет параметры активной заявки | Отмена и новая заявка через `replaceOrder`; если отмена невозможна, ошибка 30059 передаётся как `ORDER_NOT_REPLACEABLE` (ORD-5) |
| S-2.5 | Рыночная заявка исполняется мгновенно | Состояния `NEW` и `FILLED` могут прийти почти одновременно, порядок событий не гарантирован, см. правила в [03](03-order-state-machine.md) |

## S-3. Исключительные потоки

### S-3.1 Таймаут при отправке (ORD-4)
1. Сервис отправил `postOrder`, ответа нет за отведённое время.
2. Заявка переводится в `UNCONFIRMED`, пользователь видит «итог уточняется».
3. Сервис повторяет `postOrder` **с тем же ключом** (безопасно, брокер не создаст вторую заявку).
4. Если брокер вернул успех, статус `NEW`. Если вернул ошибку 30057 (ключ уже использован), сервис идёт в сверку: ищет заявку среди активных (`getOrders`) и среди недавних сделок. Найдена, значит принята; не найдена и нет сделок, значит заявка могла исполниться и исчезнуть из активных, поэтому статус остаётся `UNCONFIRMED` до ручного разбора и поднимается алерт (OQ-1).
5. Новый ключ для той же команды запрещён.

### S-3.2 Обрыв стрима (TRK-2)
1. Соединение разорвано или нет ping-пакетов дольше порога.
2. Сервис включает пометку «данные могут быть устаревшими» и начинает переподключение с нарастающими паузами (1, 2, 4, 8 секунд, потолок 60 секунд, плюс случайный разброс).
3. После восстановления выполняется сверка: активные заявки (`getOrders`) и состояние заявок, которые мы считали активными, но которых нет в списке (`getOrderState`).
4. Найденные изменения применяются по правилам переходов, уведомления дедуплицируются.
5. Пометка снимается.

### S-3.3 Отмена и исполнение одновременно (ORD-3)
1. Пользователь отменяет заявку, статус `CANCEL_REQUESTED`.
2. До обработки отмены брокер исполняет заявку.
3. Приходит событие исполнения: итоговый статус `FILLED`, отмена помечена как «не успела».

### S-3.4 Превышение лимитов (OPS-3)
1. Брокер возвращает ошибку превышения лимита.
2. Сервис ставит запросы на паузу, очередь приоритетов: отмена, затем отправка, затем сверка.
3. Пользователь получает `429` с `Retry-After`.

### S-3.5 Крупная заявка (ORD-7)
Оценочная сумма > 30 млн рублей: запрос отклоняется до отправки брокеру с рекомендацией разбить.

### S-3.6 Отказ токена или недостаточные права (SEC-2)
Ответ брокера об отсутствии прав: статус `REJECTED` (причина `AUTH`), пользователю сообщение «токен не позволяет торговать», токен не пишется в журнал.

### S-3.7 Недоступность брокера
Все вызовы завершаются ошибкой: заявки новых команд принимаются в `CREATED` только если пользователь явно выбрал режим «отложенная отправка», иначе `503 Service Unavailable`. По умолчанию (MVP) новые заявки не принимаются, чтобы не отправлять устаревшую команду, когда рынок уже изменился.

## Негативные проверки на границах

| Что проверяем | Ожидаем |
|---|---|
| Ключ идемпотентности не UUID | `400 INVALID_IDEMPOTENCY_KEY` |
| Количество 0 или отрицательное | `422` |
| Цена отрицательная, инструмент не фьючерс | `422 NEGATIVE_PRICE_NOT_ALLOWED` |
| Отмена чужой заявки | `404 Not Found` (не раскрываем существование) |
| Повтор отмены | Идемпотентно, тот же результат |
| Ключ старше месяца | Повтор считается новой командой (ограничение брокера), сервис хранит ключи дольше и отвечает из своей базы |
