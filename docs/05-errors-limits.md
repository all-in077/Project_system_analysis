# 05. Ошибки и лимиты

## 5.1. Ответы брокера и реакция OrderGuard

| Ситуация у брокера | Признак | Что делает OrderGuard | Что получает пользователь |
|---|---|---|---|
| Повтор `postOrder` с уже использованным ключом | Ошибка 30057 ✅ | Не считать ошибкой пользователя: перейти в сверку, найти заявку | Статус по результату сверки |
| Невозможно отменить при замене | Ошибка 30059 ✅ | Оставить исходную заявку, вернуть причину | `409 ORDER_NOT_REPLACEABLE` |
| Таймаут или обрыв при `postOrder` | Нет ответа | `UNCONFIRMED`, повтор с тем же ключом | «Итог уточняется» |
| Отказ по правам токена | Ошибка авторизации ⚠️ | `REJECTED` с причиной `AUTH`, токен не логируем | «Токен не позволяет торговать» |
| Превышение лимита запросов | Ошибка лимита ⚠️ | Пауза по значению от брокера, очередь по приоритетам | `429` с `Retry-After` |
| Недостаточно средств, неверный объём, торговая фаза закрыта | Отказ в ответе или событие `REJECTED` | `REJECTED` с причиной | Понятный текст причины |
| Заявка выше 30 млн рублей | Требует подтверждения по СМС ✅ | Не отправляем, отказ на нашей стороне | `422 ORDER_REQUIRES_CONFIRMATION` |
| Внутренняя ошибка брокера (5xx) | Ошибка сервера | Повтор с паузой; если не прошло, `UNCONFIRMED` | «Итог уточняется» или `503` |
| Данные об исполнении устарели | Нет событий, ping не приходит | Пометка «данные устарели», переподключение | Пометка и время последнего обновления |

Коды и тексты ошибок, помеченные ⚠️, нужно подставить из актуальной документации. Правило: **сначала смотрим на код, а не на текст**, потому что тексты меняются.

## 5.2. Ошибки собственного API

| HTTP | Код | Когда |
|---|---|---|
| 400 | `IDEMPOTENCY_KEY_REQUIRED` | Нет заголовка `Idempotency-Key` |
| 400 | `INVALID_IDEMPOTENCY_KEY` | Ключ не UUID |
| 401 | `UNAUTHORIZED` | Нет или недействительна сессия |
| 403 | `TOKEN_FORBIDDEN` | У токена нет прав на торговлю |
| 404 | `ORDER_NOT_FOUND` | Нет такой заявки у этого пользователя |
| 409 | `IDEMPOTENCY_KEY_REUSED` | Ключ уже использован с другими параметрами |
| 409 | `ORDER_NOT_CANCELLABLE` | Заявка в терминальном статусе |
| 409 | `ORDER_NOT_REPLACEABLE` | Замена невозможна |
| 422 | `VALIDATION_FAILED` | Нарушены ограничения полей |
| 422 | `NEGATIVE_PRICE_NOT_ALLOWED` | Отрицательная цена не по фьючерсу |
| 422 | `ORDER_REQUIRES_CONFIRMATION` | Сумма выше порога подтверждения |
| 429 | `RATE_LIMITED` | Превышен лимит, есть `Retry-After` |
| 503 | `BROKER_UNAVAILABLE` | Брокер недоступен |

**Формат ошибки:** единая структура `{ "code": "...", "message": "...", "details": [...], "requestId": "..." }`, описана в [OpenAPI](../api/openapi.yaml).

## 5.3. Лимиты

| Лимит | Значение | Источник | Как соблюдаем |
|---|---|---|---|
| Сумма заявки без СМС-подтверждения | 30 млн рублей | ✅ документация | Проверка до отправки |
| Срок отслеживания уникальности ключа у брокера | 1 месяц | ✅ документация | Свои ключи храним дольше |
| Запросов в минуту по методам | уточнить | ⚠️ страница «Лимиты» | Ограничитель скорости в адаптере |
| Число одновременных стримов | уточнить | ⚠️ страница «Лимиты» | Один стрим на пользователя, переиспользование |
| Глубина истории `getOrderState` | около суток | ✅ документация | Не рассчитываем на историю старше суток |

**Принцип:** значения лимитов хранятся в настройках, а не в коде, чтобы поменять их без релиза.
